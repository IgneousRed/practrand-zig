# Built-in RNG inputs

The executable supports all 297 active input-expression factories registered by
PractRand 0.96's tester: 284 generator/transform/catalog factories (including
`dummy_rng`), ten stdin/file factories and three special wrapper factories.
This count includes aliases and catalog/transform factories; it is
not a count of distinct algorithms. The vendored release remains unchanged.
Two additional factories, `ranrot_var32_fixed` and `ranrot_var64_fixed`, provide
the intended recurrence alongside the original repeating streams; see
[Ranrot choices](#legacy-and-fixed-ranrot-choices).
The generator portion is compiled from those bundled sources with Zig's C++
toolchain; statistical testing remains in Zig. No separate PractRand installation
or downloaded library is required.

```sh
python3 -B tools/zig_run.py build -Doptimize=ReleaseFast
.work/install/bin/RNG_test sfc64 -seed 0 -te 1 -tf 2 -tlmin 1K -tlmax 1G
.work/install/bin/RNG_test 'chacha(8)' -seed 123456789abcdef -tlmax 1G
.work/install/bin/RNG_test 'BDS(sfc32,4)' -seed 0 -tlmax 1G
.work/install/bin/RNG_test 'recommended_rngs(17)' -seed 0 -tlmax 1G
```

Generator/expression names are case-sensitive. The original native output width
selects standard folding; pure transforms retain their original width and byte
ordering. Quote expressions in a shell. The outer input owner retains partial
output words across reads; batching preserves the original native-word byte
stream, so read sizes do not discard bytes or advance a word twice. Threaded CPU Expanded overlaps generation and counting with two buffers,
draining each outer step before time checks and checkpoints. Threaded GPU
Expanded uses the bounded input reader for generation as well as direct stdin.
Expressions containing stream sources read on the calling thread, avoiding an
uncancellable speculative read inside a transform. Its
producer can generate ahead across checkpoints, publishing at most 1 MiB at a
time; only consumed bytes reach statistical tests. Byte limits bound generation,
while failure or time stopping can leave generated bytes unused. Cancellation
joins the producer before destroying the generator. See the [GPU resource
budget](gpu.md) for capacities and deferred input-error handling.

## Seeds and catalogs

`-seed` accepts the original 128-bit hexadecimal convention, with an optional
lowercase `0x` prefix. Thus `-seed 10` means hexadecimal 0x10. Both 64-bit words
reach the original `seed(low64, high64)` method, with its algorithm-specific
warmup. An omitted built-in seed uses a random 32-bit value from OS entropy and
prints it for replay. Entropy failure is an error. Explicit seeds do not acquire
OS entropy. On unseedable inputs (stdin, files and their pure transforms),
`-seed` remains a free-form report label; an omitted label is `unknown`.

The [fixed C8 auxiliary seed](departures-from-upstream.md#d017--fixed-c8-seed)
remains independent of the input generator seed in both result modes.
`--reference-compatible` selects statistical arithmetic, not another generator
algorithm or seed sequence.

```sh
.work/install/bin/RNG_test --list_recommended_rngs
.work/install/bin/RNG_test --list_reference_rngs
.work/install/bin/RNG_test --list-rngs
```

The first two retain original catalog names, order, positions and formatting.
The third lists registered factory names, including parameterized factories,
and labels the removed generators. As required by [UB002](upstream-bugs/UB002-removed-rng-catalog.md),
all 27 recommended slots remain in place. Positions 12–14 (`xsm64/32/16`) and
20–22 (`rarns64/32/16`) remain unavailable, with explicit diagnostics for direct,
indexed and nested selections. They are never renumbered or substituted.

Native `-ttseed[BITS]` and `--seed-walk` modes are described in
[seed testing](seed-testing.md). Native `-ttep` selects the original entropy-pooling
workflow, including basic checks and entropy-string length/report units; see
[entropy testing](entropy-testing.md). Its wrapper expression is available below.
Parameterized research generators retain upstream behavior and resource costs;
the byte vectors do not validate every possible parameter combination.

## Stream inputs and special wrappers

| Input | Interpretation |
| --- | --- |
| `stdin`, `file(PATH)` | Unknown output width; same raw bytes, unknown-format standard folding |
| `stdin8`, `file8(PATH)` | Native 8-bit words |
| `stdin16`, `file16(PATH)` | Native 16-bit words |
| `stdin32`, `file32(PATH)` | Native 32-bit words |
| `stdin64`, `file64(PATH)` | Native 64-bit words |

Files open in binary mode. The width controls folding and native draws inside
transforms; it does not parse numbers or text. Byte ordering follows the original
native-word methods. A trailing incomplete native word is discarded at EOF.
Owned file handles close when their source is destroyed; stdin stays open.

```sh
.work/install/bin/RNG_test 'file64(random-data.bin)' -tlmax 1G
.work/install/bin/RNG_test 'As8(file64(random-data.bin))' -tlmax 1G
.work/install/bin/RNG_test 'SShrink(stdin32)' -tlmax 1G < random-data.bin
.work/install/bin/RNG_test 'add(file32(random-data.bin),sfc32)' -seed 0 -tlmax 1G
.work/install/bin/RNG_test 'SeedingTester(sfc64,64)' -seed 0 -tlmax 1M
.work/install/bin/RNG_test 'RecursiveSeed64(sfc64)' -seed 0 -tlmax 1M
.work/install/bin/RNG_test 'EntropyPoolingTester(sha2_based_pool,8,8)' -seed 0 -tlmax 1K
```

Quote the whole expression for the shell. `PATH` is a literal parameter, without
embedded quote characters; spaces work inside the shell-quoted expression.
The original expression parser treats commas and parentheses as syntax, with no
filename escaping. Relative paths resolve from the process working directory.
Named sources can be nested or combined using the existing transform factories;
each named file source has its own cursor. Nested stdin sources share stdin.

`SeedingTester(RNG[,BITS])` uses the original randomized seed walk (16..128 bits,
default 128); `RecursiveSeed64(RNG)` repeatedly seeds from the preceding output.
`EntropyPoolingTester(RNG,MIN,MAX)` tests entropy strings through the original
wrapper. These are expressions in ordinary output mode: length/report units stay
bytes. Native `-ttseed` selects seed-count units and offers additional walks;
native `-ttep` selects entropy-string units and performs the original basic checks.

The wrappers retain upstream behavior and defects, except that the rewrite
fixes `EntropyPoolingTester`'s iterator-decrement crash
([UB007](upstream-bugs/UB007-entropy-pool-crash.md)) locally under
[D024](departures-from-upstream.md#d024--safe-entropy-pooling-history-insertion-bug-fix).
The entropy factory still uses MIN for both bounds, ignoring MAX
([UB003](upstream-bugs/UB003-entropy-wrapper-bounds.md)). Effective one-byte
entropy messages are rejected in both result modes: duplicate-seed rejection
can cover the entire seed space, leaving no acceptable next seed. See
[D027](departures-from-upstream.md#d027--reject-one-byte-entropy-messages).
Adding these choices does not establish statistical calibration or safety for every
parameter combination. Removed RNG slots retain UB002's explicit rejection.

EOF prints `error reading from file`, exits zero and does not fabricate a partial
checkpoint. Opening failures and real read errors exit one. The adapter defers
opening and reading until after option/seed validation. The initial buffers are
then filled in expression-construction order before
wrapper seeding, preserving which bytes each reader receives when multiple
sources share stdin. Reader resources belong to the adapter owner and close
on teardown, including when a later reader fails during priming. See
[D023](departures-from-upstream.md#d023--stream-input-lifecycle-and-errors) for
observable differences from the original reader.

## Legacy and fixed Ranrot choices

`ranrot_var32` and `ranrot_var64` preserve the captured original stream: the
initial 45-word buffer repeats. They print a warning recommending
`ranrot_var32_fixed` or `ranrot_var64_fixed`, respectively. The fixed generators
update the buffer using the intended recurrence, with zero rotation defined as
identity. They consequently produce different bytes from the original names.
The choice applies equally in normal and `--reference-compatible` result modes.

```sh
.work/install/bin/RNG_test ranrot_var32 -seed 0 -tlmax 1M
.work/install/bin/RNG_test ranrot_var32_fixed -seed 0 -tlmax 1M
.work/install/bin/RNG_test ranrot_var64_fixed -seed 0 -tlmax 1M
```

See [D029](departures-from-upstream.md#d029--explicit-legacy-and-fixed-ranrot-generators)
for the compatibility boundary. Separate retained fixed-generator controls in
`test/ranrot-fixed.json` come from original seed states and an independent Python
integer model. Tests read these controls and never regenerate them. To reproduce
into a fresh scratch destination:

```sh
python3 -B tools/build_reference.py --driver test/reference_ranrot_state.cpp \
  --output .work/ranrot-reproduction/reference-state
python3 -B tools/capture_ranrot_fixed.py .work/ranrot-reproduction/reference-state \
  .work/ranrot-reproduction/fixed.json
```

## Verification

`python3 -B tools/zig_run.py build test-unit -Doptimize=ReleaseFast` includes
`test/builtin_rngs.zig`.
It checks all 284 retained factory names, the two added `_fixed` names, and
732 retained byte vectors over 366
expressions, canonical names, native widths and both whole-buffer and irregular
reads of 4,099 bytes. Every active catalog expression is included. The two seeds
are zero and `fedcba98765432100123456789abcdef`. The original probe executes twice
per case before a vector is accepted. Ordinary tests only read the retained
`test/rng-vectors.json`; they never build the original or regenerate vectors.

The local `binarymult16` and `fibmulmix16` adapters define their unsigned
products while preserving the retained original byte vectors in both result
modes; see [UB053](upstream-bugs/UB053-binarymult16-signed-overflow.md) and
[UB055](upstream-bugs/UB055-fibmulmix16-signed-overflow.md). The ordinary vector
check exercises both whole and irregular reads, including buffered refills.
The broader [D028 remedies](departures-from-upstream.md#d028--defined-remaining-built-in-generator-arithmetic)
define the additional confirmed products and rotations while preserving original
byte fixtures. [D029](departures-from-upstream.md#d029--explicit-legacy-and-fixed-ranrot-generators)
defines the captured legacy Ranrot stream under the original names, with a
warning, and adds explicit `_fixed` names for the intended changing recurrence.
Both choices work in Debug and both result modes. ReleaseFast remains the
required full-suite configuration.

The fixture records original source/executable checksums, compiler, seed API and
the exact capture driver source. Captures used unchanged original 0.96 under
x86-64/Rosetta, Clang `-O3`, without fast math. Its native-width `TestBlock::fill`
and original seeding supply the oracle independently of the production adapter.
The fixture retains the exact earlier driver text. The maintained driver's later
ARM syntax accommodation and added input registrations leave the generator
algorithms unchanged; generator-only capture excludes the separate input factories.

Explicit reproduction uses a fresh destination under `.work/`:

```sh
python3 -B tools/build_reference.py --driver test/reference_rngs.cpp \
  --output .work/rng-reproduction/reference-rngs
python3 -B tools/capture_rng_vectors.py .work/rng-reproduction/reference-rngs \
  .work/rng-reproduction/vectors.json --architecture x86_64
```

Pass the actual reference architecture when reproducing elsewhere. The original
ARM build limitation is recorded in [UB031](upstream-bugs/UB031-unguarded-x86-headers.md).
Reproduction refuses to overwrite an existing destination. Retained originals
and their provenance belong in version control; reproduction outputs do not
replace them automatically.

The input checks additionally replay 85 retained original 4,099-byte vectors and
three entropy-wrapper metadata cases from [input-vectors.json](../test/input-vectors.json),
using the fixed [input bytes](../test/input-bytes.bin). They cover every stream
factory, width reinterpretation, BDS, self-shrinking, mixed file/RNG addition,
and seed/recursive wrappers. Whole and irregular reads must match. `input-vectors.json`
retains metadata-only upstream captures for entropy wrappers because untouched
0.96 still has UB007; rewrite entropy output is covered by [entropy testing](entropy-testing.md). CLI checks
compare file/nested-stdin reports with direct stdin in core/Expanded and
serial/threaded execution, and exercise labels, EOF and invalid requests.
The original captures execute twice and retain their driver/compiler/checksums;
ordinary tests never regenerate these fixtures.

Six additional original captures in
[multi-input-vectors.json](../test/multi-input-vectors.json) cover shared-stdin
compositions, a wrapper reading during seeding, and single-reader/independent-file
controls. They retain all 4,099 output bytes as well as hashes, canonical names,
native widths and original driver/compiler provenance. Whole and irregular
adapter reads must match. CLI checks in both arithmetic modes compare composed
expressions with those original bytes fed directly to the tester. Invalid seed,
option and expression checks keep stdin open and empty to detect premature reads;
descriptor checks cover successful teardown and failed later-reader priming.
These captures were obtained twice from the unchanged original driver and are
never regenerated by ordinary tests. Explicit reproduction of the earlier
single-source capture into disposable storage is:

```sh
python3 -B tools/build_reference.py --driver test/reference_rngs.cpp \
  --output .work/input-reference/reference-rngs
python3 -B tools/capture_input_vectors.py .work/input-reference/reference-rngs \
  .work/input-reference/input-vectors.json
```
